# 比赛演示路径

## 准备

首次启动：

    cp .env.example .env
    npm install
    npm run db:migrate
    npm run db:seed
    npm run dev

打开 http://localhost:3000。若需要恢复固定 seed，使用受保护的 npm run demo:reset；不要对带有真实或需要保留数据的数据库执行 reset。

## 主链

### 1. 工作台

从 /dashboard 开始，先讲来源渠道、客户关注点、线索→沟通→报告→成交漏斗和近期案例。重点不是数字多，而是说明后续每一步都会回流到同一个工作台。

### 2. 客户与需求

进入 /customers，新建一位客户，录入来源、预算、用途、购车时间、1～3 个关注点、风险顾虑和备注。保存后进入客户详情，展示本次需求卡。

### 3. 意向车辆与 SalesCase

在客户详情点击选择意向车辆，从现有车辆中选择 V001 或 V002。确认车辆资料、车辆状态和最近一次鉴定状态后在当前客户档案内创建 SalesCase；随后从客户档案进入车辆档案或消费者报告。已有固定数据也可以直接打开 SC-0001（李先生，安全/结构）或 SC-0002（王女士，维修成本/可靠性）作为稳定讲解入口。

### 4. 鉴定

打开 /vehicles，进入 V001 的车辆档案，再点击“进入实车鉴定台”。按区域 → 部件 → 项目操作，展示左前纵梁或底盘项目，修改一次结果/严重度并填写备注，保存后刷新确认 SQLite 已回读。未单独记录的目录项按正常基线展示；最后点击“确认其余项目正常并完成鉴定”，再运行规则评估或生成报告。标准报告会展示完整模板目录，异常优先，未单独记录项以“当前未发现该项目异常”呈现。

讲解 V003 时，可说明“车辆仍建议复检”和“这一次 Inspection 已完成”是两个不同状态，分别对应库存处置和本次鉴定事实。

### 5. 报告

从 SalesCase 生成或打开报告。先讲标准层：车辆、鉴定事实、规则结论、维修经济性和行情参考；再切换安全/结构与维修成本/可靠性两个案例，说明同一辆车的事实集合不变，个性化层只改变解释重点和排序。

报告支持打印和浏览器导出 PDF。完整事实、finding、evidence URI 和 lineage 默认收起，打印时自动展开，适合在需要时展示可追溯性。

### 6. 销售结果与复盘

在案例或报告页记录成交、暂缓或拒绝；拒绝时补充价格、维修成本等原因。回到 /analytics，指出结果、来源和关注点已经回流，形成从客户沟通到营销复盘的闭环。

### 7. 响应式收尾

将报告窗口缩到移动尺寸，展示移动端只读报告和纵向事实条目；在桌面或平板保留操作型后台。不要在现场展开未完成的生产权限、外部 API 或新媒体分析能力。
